One paired trial, charted exactly as measured.

The same coding task run without SilkWeb and with SilkWeb (registry enabled). Each chart uses its own unit and a zero baseline — different units are never mixed on one axis.

One paired trial (n = 1 pair) — not an average.Repeated runs were not measured, so no average, guarantee, or trend is claimed. Model inference cost was not independently established; no inference-cost saving is claimed from these token counts.

How to read this

Every bar starts at zero. Lengths are proportional to the values printed beside them, and each chart is scaled only to its own unit.

Percentages are computed from this single pair: for example, 103,796 ÷ 184,439 = 56.28% fewer uncached input tokens. They describe this trial only.

05 — Benchmark protocol (locked)

The B/C comparison we hold ourselves to.

The protocol is fixed before results exist, so the comparison cannot be tuned after the fact. RES-002 above is reported under this protocol as one paired trial — not as an average or a guarantee.

ArmConditionRole
AVague natural request, no SilkWebNarrative only — not primary evidence
BSame clarified spec as C, no SilkWeb toolsPrimary control
CSame clarified spec as B, SilkWeb MCP/registry enabledTreatment

Held constant: model and version (Muse Spark 1.3), reasoning effort, step cap, dependency lock, clean starting repo, machine, and permissions. Held-out tests stay inaccessible to both agents. Every trial, retry, repair, and librarian call is counted, with elapsed time and spend for both the coding model and the librarian.

Result: RES-002 — one paired trial reported in §02 above (quality, coding time, and token counts for both arms). It is a single pair, not an average. Model inference cost was not independently established, so cost is marked unavailable rather than inferred from token counts.
