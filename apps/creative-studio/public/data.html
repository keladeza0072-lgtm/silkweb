Methodology: one model run per condition against five local SQLite fixture cases. The SilkWeb condition embeds a preselected, verified business contract in the prompt before the model writes SQL. Full documentation embeds every rule instead. There is no unique accuracy advantage over full documentation: both reached 5/5.

Limitations: live contract retrieval was not evaluated, so this measures the value of the contract content, not the retrieval path. One run per condition means no variance, average, or guarantee. Development harness, not independent validation.

04: Business rules

What the contract makes explicit.

  • Paid orders count toward recognized revenue.
  • Only successful refunds linked to paid orders are deducted.
  • Duplicate refund events are counted once.
  • The selected business contract makes these rules explicit.

Scope: One model run per condition. Five local SQLite fixture cases. Development harness, not independent validation.
