SilkWeb Agents: Trusted Intelligence for AI Agents.

An approved-procedure intelligence layer between an agent's task and its execution. Instead of re-deriving how to act, a capable agent checks what is already approved, then follows it exactly, or fails closed.

01: The problem

Agents re-reason what is already settled.

Given a task, an agent typically reasons from scratch about the procedure to follow, whether its dependencies are compatible, and whether the action is safe, even when a trusted solution already exists. That repeated reasoning costs tokens, costs time, and reintroduces mistakes that review had already eliminated.

Repeated procedure reasoning

Every run re-derives steps, flags, and ordering for workflows the team has already approved, paying model calls for answers that have not changed.

Repeated compatibility checks

Stack versions, schema shapes, and capability match are re-examined per task instead of being pinned once to an approved, versioned procedure.

Repeated safety reasoning

Revoked or incompatible approaches must be re-recognized as unsafe each time, rather than rejected structurally before any reasoning is spent on them.

02: The intelligence layer

Check before you reason.

SilkWeb sits between the agent's task and execution as an approved-procedure intelligence layer. For each task the agent performs a trust check and a version check; only a procedure that passes both is returned as approved. Anything else fails closed, so the agent falls back to its normal model-driven behavior, with no SilkWeb shortcut applied.

Step 4

Approved Procedure

Exactly one pinned procedure is returned, or nothing is.

  • Rejected procedures fail closed. A procedure that was never approved is never returned (NOT_APPROVED), and the agent proceeds without it.
  • Revoked procedures fail closed. A procedure withdrawn after approval is refused on every read (REVOKED), never served from memory.
  • Incompatible procedures fail closed. An approved procedure whose version does not match the current stack or inputs is withheld (VERSION_MISMATCH), never coerced.
03: Deterministic execution

Eligible workflows run without a model call.

When a task resolves to an approved procedure and its inputs are fully specified locally, the workflow executes deterministically in the local runner, so no model call is needed for those eligible executions. Tasks that do not meet both conditions still use the model as usual; SilkWeb narrows, never replaces, model-driven work. Retrieval over MCP is read-only transport. The silkweb_agents_select tool returns guidance data only (the selected procedure, or a fail-closed reason); it never executes procedures and modifies no files. Execution happens locally, after the checks above have passed.

What this leaves out. Registry storage and lookup overhead, verification and re-verification cost, tasks with no approved procedure (which still pay full model cost), price changes, and any quality change from reuse. After those costs, a real deployment could be zero or net negative. No verified dollar saving is claimed.
