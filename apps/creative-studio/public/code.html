02: How verification works

A label is never enough.

The fingerprint is a deterministic SHA-256 over manifest metadata, the transitive source closure, covering tests, the lockfile, and the build. Evidence records the exact allowlisted command, the tests it actually executed, the Node/SQLite versions, the exit code, and byte-identical build artifacts.

Fingerprint

Bind the artifact

Sources, tests, lockfile, environment, and build config are hashed together. Change anything and the hash changes.

Run

Execute, don't assert

Only fixed argv allowlists run. Never a manifest-supplied command, never through a shell. A fresh build precedes the tests.

Evidence

Record what happened

Exit code, executed test files, scope, and limitations are written as a JSON record. Failures are preserved as failures.

Validate

Fail closed

Every retrieval recomputes the fingerprint. Missing, stale, or mismatched evidence is rejected with a named code.

Known limitation, stated plainly: collision checks use sequential same-process connections to a temporary file database. No genuine simultaneous-race coverage is claimed.

Runtime note: the registry pins the stable subset of Node's built-in node:sqlite, which upstream still flags experimental. Evidence binds the observed runtime and must be refreshed after any change.

03: Reproduction guide

Run the whole loop yourself.

No secrets, no network, no paid calls. Build the registry, run its suites, then build the MCP server. The librarian tools load the compiled registry and refuse to serve if it is missing or stale.

  • Creative Studio runs from the same Node server as this page
  • Manifests: registry-data/manifests/ · Evidence: registry-data/evidence/
  • MCP tools (search, inspect, get source, code and data lookup) are read-only; the server executes nothing and rewrites no evidence
# 1 · Registry: build + verify
cd packages/registry
npm install
npm run check

# 2 · MCP librarian server
cd apps/mcp-server
npm run check

# Tools exposed over stdio
ping → { ok: true, service: "silkweb" }
search_verified_components
inspect_verified_component
get_verified_component_source

Reuse is only real if it's checkable.

Audit the evidence records yourself: every hash, test file, and limitation is in the open.
