# RES-002 — Paired assisted-reuse performance experiment

## Hypothesis

Given the same instruction to look for certified reusable implementation,
Muse Spark 1.3 with the repaired Silk Web MCP can complete the reservation API
at equal or better held-out quality using less coding time and/or inference
tokens than Muse Spark 1.3 without Silk Web.

The experiment tests **assisted reuse**, not spontaneous/autonomous adoption.

## Pre-registered setup

- B: Muse Spark 1.3 / Meta / high reasoning / max 70 model steps / isolated
  Muse XDG profile with **zero MCP servers**.
- C: same Muse model, effort, step cap, CLI permissions, task prompt and
  starter; isolated Muse XDG profile with exactly one enabled MCP: repaired
  Silk Web's certified read-only registry.
- One frozen prompt: `experiments/tasks/RES-002-PROMPT.md`. The same exact
  bytes are supplied to B and C. Both are instructed to seek verified code
  when a tool is explicitly available, otherwise implement independently.
- The same six neutral starter files from the original RES-001 starter,
  duplicated with matching content checksums and initial Git commit hash.
- Independent evaluator: **unchanged**
  `experiments/harness/res001-evaluate.mjs`, the same 41 HTTP/SQLite
  checks with weighted score / 100 used for RES-001. Its report still
  says `benchmark: RES-001`, because the evaluator is intentionally
  unchanged; the RES-002 runner records its exact file hash and creates
  unambiguously named RES-002 records.
- No time cap: time measured across each Muse CLI coding invocation.
  Build and evaluation are recorded **outside** coding time.
- Runs are sequential B then C. One run each; **no retry** under the same
  classification, no benchmark-specific source/test corrections.
- C MCP audit is stored outside candidate workspaces and records successful
  search/inspect/source operations, source file SHA256, and truncation status.
  No source text in audit.
- The operator-prepared Git worktree containing the certified registry and
  MCP service is shared with neither candidate except through the C-only
  trusted MCP tool. Any other source copying breaks isolation.

## Measures

1. Quality: weighted held-out HTTP/SQLite score, total passed checks, and
   individual failed cases. A build failure scores 0, not a passing artifact.
2. Coding speed: Muse invocation wall clock in seconds and B/C ratio. This
   does not include dependency installation, build or evaluator.
3. Inference usage: final Muse model usage payload, separating input,
   cached input, uncached input, output and reasoning token fields.
   Cached tokens are a subset of total input tokens; do not add them.
4. Dollars: direct per-session billed USD **only if** the provider/Muse
   emits a billing field. Account credit balance differences are
   approximate at best and may include other usage; no invented rates.
5. Silk Web adoption: C source search, verified contract inspection,
   untruncated retrieval, matching SHA256 source files in candidate, and
   import reachability from the actual HTTP entry point. A mere MCP
   connection or successful search does not prove reuse.

## Interpretation limits

- This is a **single paired experiment**, not a statistically meaningful
  average across seeds/runs.
- The code-reuse guidance is explicit and equal for both, rather than
  proving autonomous tool selection under a minimal natural task.
- C's use of preverified code is a different capability condition by design.
- Source hash matches plus static import checks show integration, not
  dynamic line-level execution coverage. The held-out API evaluator proves
  runtime behavior independently.
- B/C token usage differences alone do not isolate the causal effect of
  code reuse from sampling, model trajectories or caching.
- Previous RES-001 and ADOPT-001 results are preserved separately and do
  not count as RES-002 runs.

## Operational sequence

`res002-prepare.mjs` (free, frozen starters and MCP profiles);
`npm ci` in B and C (free of model inference);
`res002-run.ps1 -Condition B -MaxModelSteps 70` (paid);
`res002-run.ps1 -Condition C -MaxModelSteps 70` (paid);
`res002-analyze.mjs` (free, read-only).

Do not claim cost/speed/quality improvement unless the actual B/C
measurements support it.
